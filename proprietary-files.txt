# --- NOT SHIPPED: the nine components above that link graphics.allocator-V1 ----
# Each of these DT_NEEDEDs android.hardware.graphics.allocator-V1-ndk while also
# needing libcommonchiutils, which links V2. Soong refuses that outright --
# "depends on multiple versions of the same aidl_interface" -- and emits no ninja
# file at all, so the whole build dies. The 67 camera components we already ship
# are unaffected: they use the HIDL allocator@4.0, not the AIDL interface.
#
# They are all optional enhancement nodes, and none is on the path to a preview:
# EVA depth/segmentation, Vidhance EIS, and the iToF depth set. arcfox has no
# iToF sensor at all -- nothing in /vendor/etc/camera mentions itof, in our build
# or in the stock dump, and no other stock component references
# libdepthmapwrapper_itof. Dropping them costs the Vidhance vendor tags and EVA
# depth; it does not cost the preview.
#
# The camera-critical blobs are NOT here: the BITML v2 CDSP skels are in
# sm8635-common, and the components that map to observed CamX errors
# (com.qti.stats.awbr, com.qti.stats.afc, com.qti.hwcfg.{ife,bps,ipe}) are
# shipped above and link no AIDL allocator.
#
# To ship them later, the version disagreement has to be resolved for real --
# either a ;DISABLE_DEPS annotation once their runtime libs are confirmed present
# on-device, or by aligning libcommonchiutils. Do not just re-add them.

# --- MotorolaSettingsProvider REMOVED: it killed system_server ----------------
# MotorolaSettingsProvider.apk declares sharedUserId=android.uid.system, so
# ActivityManager's installSystemProviders() loads it INSIDE system_server. Its
# onCreate calls ServiceManager.addService("motsettings"), and stock labels that
# name in system_ext_service_contexts:
#     motsettings   u:object_r:mot_system_service:s0
# We ship no such label and no such type, so it falls to default_android_service,
# which system_server may not `add`. Under enforcing that is a SecurityException
# thrown out of onCreate:
#     FATAL EXCEPTION IN SYSTEM PROCESS: main
#     java.lang.RuntimeException: Unable to get provider
#       com.motorola.android.providers.settings.MotorolaSettingsProvider
#     Caused by: java.lang.SecurityException: SELinux denied for service.
# system_server died this way 56 times; the boot never passed phase 100
# (PHASE_WAIT_FOR_DEFAULT_DISPLAY) even though the display stack was healthy.
#
# Dropped rather than labelled. It is the ONLY app in the build with both
# sharedUserId=android.uid.system and a <provider>, so removing it eliminates the
# whole crash class; and running a Motorola framework provider inside a LineageOS
# system_server is a standing source of crashes for no benefit. This is also
# Motorola's app payload, which is the surface this ROM exists to remove.
# The two jars, their permission XMLs and system_ext/bin/motsettings go with it:
# nothing shipped declares <uses-library> on either jar and no init rc references
# the script.
